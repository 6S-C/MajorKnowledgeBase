# W4｜第 7、9 章《评估与持续进化》

## 核心笔记

### 1. 评估不是任务结束后的打分，而是 Agent 系统的测量基础设施

普通问答可以人工看一眼答案；Agent 会多轮规划、调用工具并改变环境，仅看最后一句话很容易误判。一个可靠评估体系需要同时回答四个问题：什么算成功、任务从哪里来、谁来验证、分数怎样转化成发布或回滚决策。

~~~text
固定任务与初始状态
        ↓
Agent 与用户 / 工具 / 环境交互
        ↓
记录消息、工具调用、状态变化、费用与延迟
        ↓
结果验证 + 过程验证 + 表达质量验证
        ↓
聚合指标、失败归因、统计不确定性
        ↓
保留当前版本 / 灰度新版本 / 回滚
~~~

评估集的作用不是证明系统“已经智能”，而是把版本之间的差异转化为可重复检查的证据。公开 Benchmark 上更高的模型不一定更适合自己的任务；如果没有内部评估集，升级模型、修改 Prompt 或增加工具后都无法判断是否出现回退。

对 BCI Agent 而言，程序跑完、指标文件生成和科研结论成立是三件不同的事。评估必须分别检查运行状态、数据与协议、统计结果以及结论是否被证据支持。

### 2. 一条可复现评估任务必须把隐藏条件显式化

书中的交互型任务由四部分组成：给 Agent 的任务、用户模拟器的行为与认知边界、可重置的初始状态、可执行的验收标准。完整评估环境还需要工具接口与交互协议。

| 要素 | 回答的问题 | 常见失败 |
| --- | --- | --- |
| 数据集 | 要测哪些任务和边界情况？ | 只收集容易任务或同质样本 |
| 环境状态 | 每次是否从同一起点开始？ | 上一次运行残留影响下一次结果 |
| 工具接口 | Agent 能观察和改变什么？ | 工具抽象过高，把推理直接藏进工具 |
| Rubric / 验证器 | 哪些结果和过程才算正确？ | 只看最终文本，不核实真实状态 |
| 执行协议 | 轮次、终止、超时和重试如何定义？ | 不同模型获得不同预算，比较失去公平性 |

用户模拟器还要有事实锚定约束。它不能因为 Agent 声称“已经解决”就顺势确认，而应根据环境工具返回判断状态。否则评估会退化成两个模型互相同意，无法证明外部任务真的完成。

BCI 评估中的对应关系很直接：数据集与被试划分是任务，训练前 checkpoint 和随机种子是初始状态，训练与评估脚本是工具，指标与泄漏检查是验证器，超时、失败重试和早停是执行协议。

### 3. Pass@k 衡量能力上限，Pass^k 衡量连续可靠性

同一个成功率可以支持完全不同的产品判断：

| 指标 | 判定方法 | 更适合的问题 |
| --- | --- | --- |
| Pass@k | 同一任务尝试 k 次，至少一次成功 | 在充分探索预算下能不能做到 |
| Best@k | k 次中取最高连续分数 | 候选可由人类筛选的开放任务 |
| Pass^k | 连续 k 次全部成功且无一票否决 | 能否稳定执行退款、部署等业务任务 |

若每次运行独立、单次成功率为 `p`：

~~~text
Pass@k = 1 - (1 - p)^k
Pass^k = p^k
~~~

Pass@k 会随尝试次数快速上升，不能用它证明系统每次都可靠。对会产生副作用的操作，也不能在真实环境中“不断重试直到成功”；应在沙盒或可回滚环境中评估，并把每次失败计入可靠性。

BCI 训练常用多个 seed 报均值，但“至少一个 seed 很好”更接近 Best@k，而不是稳定提升。若一个新模块只在少数 seed 或少数被试上奏效，就不能据此称为跨被试泛化改善。

### 4. 验证器要同时看终态、过程、规则和表达

Agent 可能出现四种不同结果：事情做对且说对、事情做对但说错、事情没做却声称做了、最终结果正确但过程违反安全规则。因此单一总分不够。

| 验证层 | 主要证据 | 能发现什么 |
| --- | --- | --- |
| 终态验证 | 数据库、文件、订单、环境状态 | 外部世界是否真的达到目标 |
| 过程验证 | 工具调用顺序、参数和必要动作 | 是否跳过核验、越权或依赖违规捷径 |
| 规则验证 | 确定性政策、允许列表、安全门 | 高风险一票否决项 |
| 表达验证 | 最终答复与必要告知 | 是否误导、遗漏限制或承诺未执行动作 |

确定性验证应优先承担可编码的检查，例如文件是否存在、状态是否更新、指标是否落在合法范围。LLM Judge 适合评估语义完整性、礼貌和理由质量，但不应替代真实环境断言。

W4 的 9-1 实验正好展示了分层验证的价值：虚假承诺、隐私泄漏和过度拒绝都被过程或规则层捕获；同时，裁判把两个正常退款案例中的空工具调用轮误判为表达缺陷，形成 2 个假阳性。运行成功和评分器完全可靠必须分开记录。

### 5. 数据集设计决定评估结论能推广到哪里

评估集不应只是若干方便运行的示例，而要覆盖正常任务、边界条件、已知失败、规则冲突和分布变化。任务难度需要拆解来源，例如需要多少轮交互、多少工具、多少隐藏信息、是否存在状态依赖和长程信用分配。

设计时至少注意：

- 按真实使用分布建立基础集，同时保留高风险边界集；
- 将开发集、回归集、保留测试集分开，避免针对评估题反复调参；
- 给任务、验证器、数据来源和版本做可追踪记录；
- 去除训练数据或公开题目的污染，防止模型背题；
- 评估集随生产失败更新，但新增题不能立即成为修改者可见的唯一目标。

组件矩阵尤其需要平衡样本。W4 的 7-11 只得到不均衡的部分结果，layer3 没有有效数据，不同配置覆盖的案例也不一致，因此不能直接把组间均值差异解释成嵌入或重排器的提升。实验未完成本身就是评估结论的一部分，不能把多个活动的部分结果拼成完整矩阵。

### 6. LLM-as-a-Judge 必须先校准，再用于规模化评分

LLM Judge 的优势是能处理开放回答和多维 Rubric，风险是受提示、输入视图、顺序、模型偏好与同源偏差影响。可靠用法应包含：明确维度、离散等级锚点、正反例、结构化输出、人工标签校准和分歧审查。

W4 记忆评分使用四个维度：

| 维度 | 关注点 | 与传统检索指标的区别 |
| --- | --- | --- |
| Precision | 回答中的事实是否准确、有依据 | 不是“命中文档中有多少相关项” |
| Recall | 应提到的关键信息是否覆盖 | 不是检索 recall@k |
| Reasoning | 是否正确关联人物、时间和条件 | 关注综合推理，不只是事实数量 |
| Proactivity | 是否发现相关需求并提出有依据的帮助 | 主动不等于擅自行动 |

7-3 实验先用 6 条预置回答校准评分器，其中错误账号数字与无记忆回答触发幻觉否决。这说明一票否决可防止平均分掩盖关键事实错误；但 6 条校准不能证明评分器适用于所有 60 案例。回答模型与裁判同源时还可能共享偏差，应保留人工样本或使用不同来源的裁判做交叉检查。

### 7. 失败归因应定位“第一个可纠正错误”，而不是只给整条轨迹贴失败标签

最终失败常由早期一个判断错误逐步放大。轨迹分析要从环境状态和工具结果出发，找到模型第一次拥有足够证据却仍做错的节点，再区分错误来自观察、推理、工具选择、参数、执行、验证还是沟通。

~~~text
任务失败
  ↓ 回放状态与动作
第一个与正确轨迹分叉的节点
  ↓
当时模型看到了什么证据？
  ↓
是信息没进入上下文、进入后未使用，还是工具 / 验证器错误？
  ↓
选择 Prompt、知识、程序、工具或数据层面的修复位置
~~~

端到端回归任务检验完整系统是否恢复；轨迹前缀回归则从错误发生前的状态继续运行，用来判断修复是否针对真正根因。只重跑整条任务可能被随机性掩盖，也难以区分前面偶然换路和局部修复的贡献。

“做对了但说错了”也要独立归因。例如工具已成功修改状态，最终答复却声称失败；反过来，答复很自信但工具从未执行。轨迹记录必须保留 tool_calls、工具返回、状态变化和最终文本，不能为了简化只保存对话 content。

### 8. 模型选型要共同看质量、任务成本、延迟和失败率

模型单价低不代表完成任务更便宜。Agent 的总成本由多轮输入、重复前缀、缓存命中、输出长度、工具调用、重试和失败后人工处理共同决定。

~~~text
任务成本 ≈ Σ[(未缓存输入 × 输入单价)
             + (缓存输入 × 缓存单价)
             + (输出 × 输出单价)]
          + 工具 / 基础设施 / 重试成本
~~~

第 7 章成本分析应按每次调用记录模型、token、缓存、延迟、状态码与重试，而不是只看总账单。还要把预热、正式请求和失败尝试分开，币种与单价版本写入元数据。

W4 的 7-9 单次受控实验中，“缓存＋压缩”相对基线的估算成本下降约 42.1%，但与“仅缓存”差距很小，而且四组输出长度并不完全一致。这能说明成本构成，不能证明压缩后任务质量保持不变，也不能由一次固定顺序运行推出普遍性能结论。

### 9. 统计显著性与可观测性决定“提升”是不是随机波动

只报告平均值会隐藏样本差异和运行随机性。评估至少应记录样本量、重复次数、随机种子、方差或置信区间，并尽量使用配对设计：同一任务、同一初始状态分别运行旧版和新版，再比较逐题差值。

| 问题 | 合适做法 |
| --- | --- |
| 单题多次采样是否稳定 | 报单次成功率、Pass@k、Pass^k 与分布 |
| 两版本是否真的不同 | 配对差值、bootstrap 置信区间或适当显著性检验 |
| 改进来自哪个模块 | 消融实验，只改变一个机制 |
| 线上变化是否有业务价值 | A/B 测试，同时设置护栏指标 |
| 失败为何发生 | 保存逐调用轨迹、状态、成本和验证器输出 |

统计显著不等于实际重要，实际重要也可能因样本太少未达到显著。结论应同时报告效应大小、区间和业务门槛。

可观测性不是多打印日志，而是让一次结果可以回到具体任务、版本、请求和文件。隐私信息应最小化收集或脱敏；用于分析的日志与对外服务权限分开。特性开关要记录“配置上启用”和“运行时实际触发”两个状态，否则 Hybrid 名义上存在检索能力，却可能几乎从未调用。

### 10. 记忆系统评估必须拆开“存进去、找出来、用正确”

记忆系统的最终回答得分混合了多个环节：抽取是否正确、写入是否完整、检索是否召回、重排是否合理、模型是否正确使用证据。仅凭答案分数无法反推出检索质量。

W4 的 7-4 在同一 60 案例套件中比较 JSON Cards、RAG 与 Hybrid。该次运行中 JSON Cards 总体 reward 最高，RAG 在 layer1 最高、在 layer2/3 较低；但 Hybrid 的 60 个案例只有 1 个实际调用检索工具。因此结果只能说明这套数据、实现和裁判下的表现，不能概括为某一种记忆架构普遍更优。

更完整的记忆评估应同时保存：

- 抽取事实与原始会话的对应关系；
- 卡片或索引写入结果、版本与更新时间；
- hit@k、recall@k、MRR 等检索指标；
- 最终回答的多维 Rubric 与幻觉率；
- 工具是否实际触发、调用次数、延迟和成本；
- 人物消歧、时间更新、冲突信息与跨会话综合等分层结果。

这样才能判断问题发生在存储、检索、推理还是评分，而不是看到一个总分后凭印象修改系统。

### 11. 持续进化不是不断追加记忆，而是把学习信号写入合适载体

Agent 可以从环境状态、验证器、用户纠正、人工审批、失败轨迹和长期指标中获得学习信号。不同问题应写入不同载体：

| 更新载体 | 适合沉淀什么 | 主要风险 |
| --- | --- | --- |
| 知识 | 事实、案例、来源与适用条件 | 过期、冲突、检索不到 |
| 指令 / Skill | 可描述的流程、边界与经验规则 | Prompt 膨胀、规则互相覆盖 |
| 程序 / Harness | 可确定执行的约束、检查和工作流 | 代码缺陷、权限扩大、维护成本 |
| 模型参数 | 难以显式表达的模式、风格和感知能力 | 训练成本、遗忘、难回滚和难归因 |

默认应优先做局部、可解释、可验证的更新。能用确定性程序保证的规则，不应只在 Prompt 里提醒；一条新的事实也不值得通过微调写入参数。选择更新位置的核心不是“信息是否重要”，而是它能否被外部符号完整表达、执行时需要多强保证，以及未来怎样验证和撤销。

W4 的 9-9 用 static、append-only、evolving 三臂区分三种行为：不持久化、只追加旧经验、版本化替换并保留废止历史。本次受控任务中，append-only 能迁移旧能力却继续引用已废止的 20 kg 规则；evolving 能启用 23 kg 新规则并保持未变化能力。这验证的是记忆生命周期和动作遵从，不是模型自主训练或开放式规律发现。

### 12. 可靠进化需要在线执行与离线学习分离，并保留不可修改的可信根

生产系统不应让一次在线失败或网页中的恶意内容立即改写正式能力。更稳妥的是双循环：

~~~text
在线执行循环：完成任务 → 保存不可变轨迹 → 产生评价信号
                                      ↓
离线进化循环：聚合证据 → 找根因 → 生成最小更新提案
              → 迁移集 / 保留集 / 安全集验证
              → 人工审批或灰度 → 发布 / 回滚 / 淘汰
~~~

新知识、Prompt、Skill、程序和参数先进入待验证区，不能直接服务真实流量。生成更新的 Agent 无权修改批准自己的验证器、测试集、发布门槛、审计日志和稳定版本备份；否则它只需降低阈值或删除失败用例，就能把退化伪装成进步。

长期运行还需要“睡眠学习”：定期合并重复经验、标记冲突与适用范围、淘汰过期规则、重建索引并保留版本。遗忘不是缺陷，而是容量受限系统保持一致性的必要机制。负面结果和被拒绝提案也应保存，避免 Agent 反复探索已经证伪的路径。

对 EEG/BCI 科研 Agent，W4 的最终交付应落成一份跨被试评估协议：固定数据版本、预处理、LOSO/跨会话划分、随机种子、基线、指标定义、效应量与显著性方法；每次实验保存配置、源码、环境、日志和结果。新经验只能作为版本化提案进入科研记忆，经保留被试、旧任务回归与人工审查后再成为正式 Skill。这样，系统记录的不只是“哪个模型分数高”，还包括尝试过什么、为什么失败、证据来自哪里，以及新规则是否破坏了原有能力。
