# W0｜第 1 章《AI Agent 入门》

## 核心笔记

### 1. 两个公式不是两套概念

```text
最小工程公式：Agent = LLM + 上下文 + 工具
生产工程展开：Agent = Model + Harness
Harness = 上下文管理 + 工具接口 + 约束 + 验证 + 纠正
```

- **LLM / Model（大脑）**：根据当前信息决定下一步；它不直接读取网页、文件或数据库。
- **上下文（眼睛）**：模型这一次真正能看到的信息；没有送入上下文的信息，对模型来说等同于不存在。
- **工具（手脚）**：模型读取或改变外部世界的受控接口。
- **Harness（运行与治理层）**：组装上下文、声明并执行工具、限制权限、检查结果和处理失败。Harness 在 Agent 边界内；网页、数据库、文件、用户等被交互的对象属于 Environment（环境），不属于 Harness。

对 BCI/ Agent 的迁移：模型不是直接“知道你的 EEG 数据和实验结果”，而是要由 Harness 把数据摘要、实验协议、历史运行记录等放进上下文，并把“运行预处理”“读取指标表”等能力设计成有边界的工具。

### 2. ReAct：想 → 做 → 看 → 再想

ReAct = Reasoning + Acting。一次最小循环如下：

```text
静态前缀 = 系统提示词 + 工具定义
轨迹 = [用户任务]

循环：
  context = 静态前缀 + 轨迹
  decision = Model(context)
  轨迹追加 decision
  若没有工具调用：返回最终回答
  Harness 校验并执行工具调用
  轨迹追加工具结果（观察）
```

**轨迹（trajectory）** 是一个任务内不断增长的动态消息历史：用户消息、模型回复（reasoning / content / tool_calls）和工具结果。系统提示词与工具定义通常不写入轨迹，因为它们是每轮都会附在最前面的静态前缀。

| 进入每次 LLM 调用的东西 | 作用 | 不应混淆为 |
| --- | --- | --- |
| 系统提示词 | 身份、边界、规则、必要的状态 | 用户的临时任务 |
| 工具定义 | 工具名、用途、参数 schema | 工具已经执行出的结果 |
| 用户消息 | 当前任务和输入数据 | 模型的内部知识 |
| assistant 消息 | 已采取的决策、文本、工具调用 | 外部世界发生的事实 |
| 工具结果 | 对行动的观察与反馈 | 工具定义本身 |

`reasoning` 记录“为什么这样做”，工具结果记录“实际发生了什么”。在某些任务里前者可从后者重建，未必是最关键的上下文；而缺少工具结果会切断闭环，Agent 可能不断重试却不知道工具已经返回了什么。

### 3. 上下文消融实验目的

实验 1-1 固定任务和模型，只移除一类上下文信息，比较的是组件贡献。

| 组别 | 移除项 | 应重点观察 | 典型风险 |
| --- | --- | --- | --- |
| `full` | 无（基线） | 是否正确完成、轮数、工具调用数 | 基准 |
| `no_history` | 先前 ReAct 历史 | 会不会重复调用、变慢 | 遗忘已做过的事 |
| `no_reasoning` | 先前模型思考字段 | 计划是否变差；注意模型差异 | 推理过程不一定不可替代 |
| `no_tool_calls` | 工具定义 | 是否完全没有工具调用；最终回答是否有依据 | 可能给出看似完整但来自参数记忆的答案 |
| `no_tool_results` | 工具执行结果的内容 | 是否盲目重试、触及迭代上限 | 闭环被切断 |

特别注意：`no_tool_results` 的标准实现是保留协议要求的 tool 消息、但令内容为空。若改为可见的 `marker` 占位符，模型额外看到了“结果被隐藏”的信号，已经是另一个实验，不能和标准消融混写。

### 4. 工作流、Agent 与 Harness

| 模式 | 路径 | 更适合 | 代价 / 风险 |
| --- | --- | --- | --- |
| 工作流 | 开发者预先写定 | 支付、审批、固定科研流水线等强约束流程 | 面对例外不灵活 |
| 自主 Agent | 模型根据环境反馈决定下一步 | 检索、调研、编码、开放式排错 | 成本、循环与复合错误风险更高 |
| 混合 | 关键边界用工作流，探索部分用 Agent | 大多数真实系统 | 要清楚划分责任边界 |

不要一开始就堆复杂的多 Agent 流程。先给足必要上下文和可组合工具；只有当业务规则必须固定，或评估持续揭示稳定失败时，才把它升级为确定性流程、验证器或独立审核角色。

### 5. 安全与可靠性：三层护栏

1. **上下文层**：控制模型看到什么，例如来源标注、提示注入检测、输入长度限制；它能降低风险，不能作为唯一防线。
2. **执行层**：在工具生效前做最小权限、参数校验、沙盒、人工确认和输出检查。
3. **数据层**：由数据库约束、行级权限、受信任访问上下文等机制决定世界最终能被怎样修改。

人为介入的触发条件至少包括：到达重试/迭代上限，以及涉及不可逆或高风险操作。对科研 Agent，可把“更改原始数据、覆盖历史结果、提交运行任务”标成需确认的高风险动作。

### 6. 五种设计纪律

- **提议者—审核者**：产出者和审核者不共享同一上下文，自审不当作独立验证。
- **渐进式披露**：先给目录/摘要，细节按需加载，避免上下文膨胀。
- **只增不改**：日志和轨迹追加保存，利于缓存、重放和审计。
- **边界集 + 保留集**：既测“应当变好”的样本，也测“不应被影响”的样本。
- **最小 diff + 可回滚**：一次只改少量可归因的内容，保留回退路径。
