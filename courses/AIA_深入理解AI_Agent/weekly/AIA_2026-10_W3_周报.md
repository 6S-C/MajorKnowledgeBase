**本周学习总结与心得**

一、工具不只是给模型增加几个函数

学习第 4、5 章后，我对 Agent 工具的理解更加具体。工具不仅负责执行搜索、读写文件或运行代码，还要规定输入输出、权限边界、失败返回和验收方式。执行工具实验中，语法错误和越界路径能够被拦截，但完整流程仍可能因为目录初始化或 Shell 环境不同而失败。这说明工具能否调用只是第一步，真正可靠还需要 Harness 对路径、权限、返回状态和异常进行约束。

二、工具越多不一定越好

主动工具发现实验比较了全量注入、预筛选和运行时发现三种方式。运行时发现明显减少了需要放进上下文的工具说明，但也增加了发现工具的调用次数；一次性预筛选则可能漏掉完成任务所需的能力。这让我认识到，工具组织需要同时考虑上下文开销和候选工具覆盖率，不能只追求工具数量少或 token 使用低。本次使用的是离线 mock 路由，因此结论主要说明机制差异，还不能直接代表真实模型的选择能力。

三、Coding Agent 的关键是形成可验证的闭环

Coding Agent 实验中，Agent 经历了查看文件、执行代码、读取报错、修改内容和重新测试的过程。命令执行失败并没有直接结束任务，而是作为新的上下文帮助模型调整下一步操作。这个过程让我看到，Coding Agent 的价值不只是生成代码，而是利用工具和反馈持续修正结果。不过，程序正常退出或模型回复“已经完成”都不能作为最终依据，还需要使用独立测试检查需求是否真正满足。

四、DeepTutor 知识库的质量来自整理与验收

DeepTutor 实践让我进一步认识到，把资料上传到系统并不等于完成知识库建设。原始文件格式、公式完整性、题目与答案对应关系、片段编号和统计口径都会影响检索结果。第二章题量统计无法直接通过多次语义检索得到可靠答案，后续改为根据完整题目索引统计，并把范围和口径写入知识库。这个过程说明，解释类问题可以依靠检索与模型生成，而数量统计等需要完整覆盖的任务更适合先由程序或人工核对。

五、团队合作需要统一规则和责任边界

本周的团队实践不是简单地把文件集中到一个文件夹，而是明确课程负责人、互测成员和管理员的职责。统一目录、题目 ID、资料清单、版本和验收记录后，其他成员才能定位问题并复用成果。Git 负责保存文本资料和修改历史，大型文件通过共享位置管理，DeepTutor 索引则由管理员根据清单重新建立。这样既能避免共享密钥和本机运行环境，也能让每次修改有来源、有审核、有反馈。

六、这些经验可以继续迁移到 EEG/BCI 实验

本周实现 BCI 指标汇总工具时，我进一步注意到统计口径的重要性。同一被试运行多个随机种子时，应先进行被试内汇总，再进行被试间比较，不能因为某个被试运行次数更多就获得更高权重。进入下一周的 Agent 评估与持续进化学习后，我会继续关注数据划分、随机种子、评价指标、成本和失败轨迹，并把这些条件固定到实验记录和工具验收中，使后续结果能够被核对和复现。
