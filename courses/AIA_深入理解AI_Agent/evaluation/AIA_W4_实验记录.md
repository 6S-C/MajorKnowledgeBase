## 1. 2026-10-28｜实验 7-9：Agent 任务成本分析

### 1.1 实验目的与方法

这项实验主要想弄清楚：同一个 8 轮客服任务，保持前缀稳定和压缩历史内容分别能省多少成本。先用仓库历史轨迹离线复算，再用 Kimi 跑“不缓存不压缩、仅缓存、仅压缩、缓存＋压缩”四组，记录输入、缓存和输出 token。工具返回由样例预设，所以重点看上下文与用量变化，不把它作为真实退款业务的成功率测试。

在线模型为 `kimi-k2.6`，端点 `https://api.moonshot.cn/v1`，关闭思考，temperature=0.6，max_tokens=160。缓存组使用稳定前缀；非缓存组通过变化的头部破坏前缀稳定性；压缩组将较早的工具返回替换成摘要，保留最近两轮完整返回。

### 1.2 实际结果

离线正式复算窗口为 23:25:50–23:25:51，约 0.34 秒，不调用 API。输入是仓库历史 gpt-4o-mini 轨迹，采用历史 USD 单价：

| --- | ---: | ---: | ---: | ---: |
| 不缓存、不压缩 | 20,700 | 0 | 0.003776 | 基线 |
| 仅缓存 | 20,386 | 13,568 | 0.002707 | −28.3% |
| 仅压缩 | 16,177 | 0 | 0.003115 | −17.5% |
| 缓存＋压缩 | 16,035 | 6,144 | 0.002643 | −30.0% |

在线第一次尝试于 23:26:03–23:26:25 失败。调整请求节奏后，第二次于 **23:38:35–23:55:18** 完成，退出码 0；32 次正式调用加 16 次预热，共 48 次成功、0 次重试。

在线采用配置中保存的 CNY 参考单价：每百万未缓存输入 6.50、缓存输入 1.10、输出 27.00。成本公式为 `[(输入−缓存)×输入价＋缓存×缓存价＋输出×输出价] / 1,000,000`。

### 1.3 异常、处理与结论限制

- 首次失败是账号组织级 **RPM=3** 限流，返回 429，不等于余额不足。加入全局至少 21 秒的请求开始间隔后完成；预热、正式请求与重试共用限速器，SDK 隐式重试关闭。
- 成功轮墙钟约 16 分 43 秒，包含预热和主动等待。四组正式请求的 API 耗时之和约为 58.47、40.31、52.55、59.41 秒；节流等待不应算作模型响应时间。
- 本轮缓存＋压缩成本最低，但与仅缓存差距很小。B 组有一轮输出较短，单次输出长度也参与成本差异，不能把全部差额归因于压缩。
- 离线 USD 轨迹和在线 CNY 实测分别解释；旧轨迹延迟不等于本地复算耗时。首次在线失败前的成功请求数未完整记录，不将其费用补成零。
- 这是单次、固定顺序的四组观察，没有重复实验或任务质量的独立评分；本次支持成本构成的分析，不能证明更省钱时业务质量一定保持不变。金额为估算，TTFT 与实际账单未记录。

## 2. 2026-10-30｜实验 7-3：记忆评分 Rubric 校准

### 2.1 实验目的与方法

这项先从评分器入手，看看 precision、recall、reasoning、proactivity 四个维度分别怎样打分，什么情况下会触发幻觉否决。这里用的是 **1–4 档的 Rubric 评分**，与检索实验按命中数量计算的 precision/recall 要分开理解。

输入来自第三章 fixture：银行、车辆消歧、旅行综合三个来源案例，共六条预置回答；其中一条银行回答显式改错账号数字。回答不是本轮记忆系统自动生成的，因此该项是裁判校准，不能当成完整 60 案例系统对照。

裁判为 Kimi `kimi-k2.6`。reward 为四维 `(score−1)/3` 的平均，检测到幻觉时归零；passed 要求前三维均至少 3 且没有幻觉，proactivity 参与 reward，但不单独决定 passed。

### 2.2 实际结果

真实运行时间 **21:23:20–21:26:41**，约 200.9 秒，退出码 0，6/6 条完成；六次调用均一次成功。

| 样本 | P / R / Rea / Pro | 幻觉否决 | reward | passed |
| --- | --- | --- | ---: | --- |
| bank_complete | 4 / 4 / 4 / 4 | 否 | 1.000000 | 是 |
| bank_concise | 4 / 3 / 4 / 2 | 否 | 0.750000 | 是 |
| bank_no_memory | 1 / 1 / 1 / 1 | 是 | 0.000000 | 否 |
| bank_wrong_digit | 1 / 2 / 1 / 3 | 是 | 0.000000 | 否 |
| vehicles_disambiguation | 3 / 3 / 4 / 3 | 否 | 0.750000 | 是 |
| travel_synthesis | 4 / 3 / 4 / 4 | 否 | 0.916667 | 是 |

按原始评分独立复算 reward 与 passed，全部一致。输入 **20,265 token**（内含缓存 3,072）、输出 **6,950 token**，总计 27,215；缓存已在输入中，不能再加一次。金额和 TTFT 未记录。

### 2.3 异常、处理与结论限制

- 错账号被幻觉否决正确检出；无信息回答的“我无法访问账户信息”也被裁判判成幻觉，属于拒答与能力性陈述的边界争议。该样本四维本来全为 1，即使取消否决，reward=0、passed=false 仍不变。
- **结构正确不等于理由正确**。旅行样本的评分理由把待评回答没有明说的加急办理、时间缓冲计算等信息归功于回答；这些信息即使在来源中存在，也不能证明回答已经表达了它们。
- 旅行案例的评估标准与原对话在办理时长、有效期要求上存在内部冲突。本次只记录数据集内部不一致，不把样本当成现实旅行建议的验证。
- 部分 evidence 是摘录、拼接或裁判总结，不应全部称为逐字引文。简短银行回答的补充信息与车辆措辞扣分也存在裁量空间，不能认证“其余评分全部合理”。
- 保留原始分数，不为消除争议而重新评分。只有六条、单次运行，没有独立专家标注，不报告裁判准确率或评分稳定率。

## 3. 2026-10-31—11-01｜实验 7-4：三种记忆系统对照

### 3.1 实验目的与方法

这项把评分器接到实际记忆系统后面，用同样的 60 个案例比较 advanced_json_cards、RAG、Hybrid，共 **180 条轨迹**。三层各 20 案例，分别涉及单对话事实、多实体消歧与跨对话综合。每个系统先构建记忆、再回答问题，最后按四维 Rubric 和幻觉否决评分。

本轮为百炼单 API 改造版：回答、抽取、语义重排和裁判使用 qwen-plus，嵌入使用 text-embedding-v4。JSON Cards 将结构化记忆放入上下文；RAG 按需检索；Hybrid 同时提供卡片与检索能力。实际保存的聊天请求 temperature=0，关闭思考。

### 3.2 实际结果

Smoke 于 10-31 22:27:55–22:30:26 完成 3 条轨迹。Full 从 **10-31 22:31:09** 开始，经五个会话，到 **11-01 02:45:54** 完成；最终 60 案例×3 系统各一个唯一单元，180 条均 status=ok。

status=ok 表示轨迹执行并产生评分，不等于回答达到成功门槛。主结果按原始 JSON 复算如下：

| 系统 | layer1 reward | layer2 reward | layer3 reward | 总体 reward | 成功数 | 幻觉否决 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| JSON Cards | 0.8500 | 0.8917 | 0.9333 | **0.8917** | 53/60（88.3%） | 4/60 |
| RAG | **0.9083** | 0.5458 | 0.4875 | 0.6472 | 39/60（65.0%） | 19/60 |
| Hybrid | 0.7750 | 0.8125 | 0.7083 | 0.7653 | 45/60（75.0%） | 11/60 |

| 系统 | 平均 steps | 平均工具调用 | 平均轨迹延迟 |
| --- | ---: | ---: | ---: |
| JSON Cards | 1.000 | 0.000 | 95.6 s |
| RAG | 2.000 | 1.000 | 20.3 s |
| Hybrid | 1.017 | 0.017 | 98.1 s |

Hybrid 在 60 个案例中仅一个发生了检索工具调用，不能把本轮结果解释成“每次都同时充分利用卡片与检索”的对照。轨迹延迟包含相应的记忆构建和调用开销；共享开销可能被分配到不同系统记录，不能将这些均值简单求和当墙钟时间。

Full 五个会话共 **841 条成功回执＋4 条错误回执**；按成功回执及当时单价独立复算约 **3.123856 CNY**。Smoke 另约 **0.034745 CNY**，两者合计约 **3.158601 CNY**，均非账单。四维评分及幻觉归零复算 180/180 一致。

### 3.3 异常、处理与结论限制

- 四次中断分别为三个连接级异常，以及一次 embedding 接口返回 HTTP 400、`InternalError: Receive batching backend response failed!`。无 HTTP 响应的连接错误不能进一步定位为“本地网络瞬断”；收到错误也不意味着服务器一定没有处理或计费。
- 每次按完整案例检查点显式恢复。已完成案例不再运行，但失败案例此前成功的子调用会重复，因此不能写成整个恢复过程“零重复付费”。原始失败现场保留。
- 本套件中 JSON Cards 的总体 reward 最高，RAG 在 layer1 得分最高、在其余两层较低。这是该数据、实现与同源裁判下的观察；不同层是不同案例，不能仅凭层均值变化断言复杂度带来了某种因果效果。
- 整理时发现，之前对温度、Hybrid 平均调用次数的记录有误，已根据请求参数和结果 JSON 更正。180 条的总体平均 reward 为 **0.7681**，之前写成 0.7014。
- 程序按 record 汇总的名义成本约 3.6968 CNY，其中涉及索引费用的重复分摊和 token 类型归集，与逐次 API 用量估算不同。因此这里按回执计算整次费用，各系统的名义成本只用于查看程序怎样记账。
- 回答和裁判同源，且 7-3 已发现 Rubric 与数据集问题。单次运行的成功率属于本评分器定义，不能当作独立专家认证。检索 hit@5/recall@5/MRR 在该实验未采集，不能用答案得分反推检索召回率。

原子集的直接停止点为 layer2_20：一次 gold 片段标注请求成功返回 23 个带 `CHUNK ` 前缀的 ID，旧解析仅接受裸 ID，精确匹配得到空集。程序因此生成 24 条 error 并触发全局停止；不是 24 次 API 请求分别失败。其余在途案例受熔断影响中断。

最小修复仅去掉固定前缀和两端空白、去重，再与当前案例合法 ID 精确匹配；不修改数字、不做模糊匹配，未知 ID 仍不接受。原始失败响应离线回放为 23/23 合法；两次恢复的在线回执也实际经过了此前会失败的前缀路径。

两次恢复均因连接级异常熔断，具体故障位置未能确定。第二次已有 layer2_08/09/20 各 5/5/4 条新有效轨迹，均使用 embedding-v1，覆盖三种重排；这些记录已保存，14 条 reward 复算一致。**新完整案例检查点为 0，不等于有效新轨迹为 0。** 第二次会话为 120 旧＋14 新，共 134 条 status=ok，与父活动 141 条是不同结果集合，不能相加。

### 4.4 异常、费用与结论限制

## 6. 2026-11-01｜实验 9-9：持续进化评估

### 6.1 实验目的与方法

最后这项关注的是：系统记住一条规则后，如果规则变了，还会不会继续照旧回答。样例用退款、身份核验、行李额度构成 14 个顺序任务，分为学习、迁移、规则变化与保持四个阶段。行李额度中途从 20kg 改成 23kg，同时保留退款和身份核验任务，用来检查新规则是否生效、旧能力是否还在。

三个臂共享相同模型与任务顺序：static 不持久化反馈；append_only 保存观察但始终激活第一版规则；evolving 由程序管理版本并启用新规则、保留 superseded 历史。模型负责逐题选动作，记忆更新由程序执行，不是模型自主训练或改写参数。

模型为同一豆包 ARK 模型，关闭思考，temperature=0，max_tokens=160。三个种子 8601/8602/8603，每臂每种子内部 14 题串行，组合之间最多 3 路并发，共 **126 次真实模型决策**。

- 本项没有运行失败，但必须限制结论：提示明确给出动作词表、无记忆时的基线和有记忆时的执行规则；这里验证的是受控的记忆生命周期与动作遵从，不是开放式自主发现规律。

## 8. 本周个人总结与心得

这周学习第 7、9 章后，我开始更关心一项结论是怎样被证据支持的。程序正常退出、评分 JSON 格式正确、实验达到预期效果，是三件不同的事。9-1 退出码为 0，但两个表达误判仍然存在；7-11 有有效结果，却没有完成矩阵。把这些状态分别写清楚，比用一句“实验通过”更能说明我实际做到了哪里。

成本实验让我把上周对缓存的认识推进了一步。仅缓存组在这次 Kimi 调用中节省明显，缓存加压缩也取得最低成本，但预热本身需要额外调用；为了适应 RPM=3 而等待的时间，又不能算成模型的响应延迟。我以后记录开销时，会把正式请求、准备开销和失败尝试分开，也会同时检查任务质量，避免只因为 token 少就认为方案更好。

模型裁判的校准是本周最直接的提醒。旅行样本的来源材料和评估标准有冲突，裁判又会把来源里有、回答里没说的信息归功于回答；正常工具调用轮的空文本也被判成表达问题。这些情况说明，要求裁判给依据很有必要，但依据非空不等于推理成立。我需要先确认裁判看到了什么、评的是什么，再判断分数是否有意义，而不是为了让结果整齐去修改原始标签。

记忆系统对照让我看到，结构化卡片在本套件中得分最高，不代表卡片在所有任务上都更好。Hybrid 提供了检索工具，模型却很少真正调用；7-11 又因为案例未跑齐，各组件的均值对应不同样本。整理这些记录后，我更能理解公平对照为什么要固定案例和分母。0.667 的整体保持率与 0 的当前行李规则保持率看似矛盾，实际只是回答了不同的问题，指标名字必须跟计算范围一起记录。

持续进化实验让我分清了“存下新信息”和“启用新规则”。append_only 已经保存 23kg 的信号，仍沿用 20kg；evolving 的版本管理让后续动作使用新规则。不过，这个更新由程序执行，不能写成模型自己学会了修改知识。结合 EEG/BCI 方向，我会把数据集版本、被试与 session、预处理参数、训练种子和评价协议纳入实验记忆；协议变化后保留旧版和来源，再明确当前有效版本，避免新旧指标混算。

7-11 两次恢复没完成，也留下了可用的教训：14 条部分结果不是零，但它们还不能支撑完整矩阵结论；每跑完一个完整案例才存检查点，对长案例来说粒度偏大。本周我选择把未完成状态如实保留。后续设计自己的 BCI 实验助手时，会优先考虑每个独立单元完成后保存结果、验证恢复条件和保留失败来源，让一次中断尽量不需要重复已经完成的工作。
