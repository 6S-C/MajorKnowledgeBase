# 第四周实践反思：用 DeepTutor 整理概率论，我需要验证什么

记录人：朱家鹏  
日期：2026年10月25日  
课程范围：高等教育出版社浙大《概率论与数理统计》第五版前三章

这次我负责概率论课程，在 Agent 辅助下推进 DeepTutor 资料准备。已经整理了前三章原创讲义、45道原创练习及参考解析，建立了题目索引和交付清单，也下载了三份真实的高校教师课件，并实际查看了第五版第三章的官方样章。目前还没有配置模型、执行知识库导入或做真实检索问答。因此，我现阶段的认识主要来自资料整理、来源核查和源码静态阅读，不能写成系统已经改善了我的学习效果。

## 一、资料整理得很快，反而更需要重新检查目标

这次最值得反思的地方，是原创资料包很快就能形成：讲义有章节，练习有解析，文件检查也能通过。但对照交付要求时，仍然缺少指定版本的教材原件与原书习题。原创讲解可以帮助理解概念，却不能证明课程资料已经收齐，更不能代替对教材题号、原页码和教师答案的核对。

我由此看到，Agent很擅长完成一个形式清楚、能够快速检查的任务，但这个任务可能只覆盖了真实目标的一部分。如果我只要求“生成前三章资料”，就容易把生成速度当成完成度。更准确的要求应是：哪些内容来自课程原件，哪些是补充编写，哪些已经核对，还缺什么证据。评价工作是否完成，要回到用途和验收条件，不能只看文件数量和目录是否整齐。

对我自己也是如此。如果全部内容由Agent整理，而我不能解释某道题为什么选择这个模型，那么我只是拿到了资料，还没有把它转化成自己的能力。后续我需要从整理者的角色回到学习者的角色，独立完成推导，再使用系统帮助查错。

## 二、来源核查本身就是一次判断训练

整理开始时，辅助Agent仅根据文件格式，把文件夹中的四份PDF初步称作课件。读取正文后才发现，它们实际是上课点名册。这说明“文件能打开”和“文件适合入库”之间还隔着内容判断；一个自动流程即使没有报错，也可能一直在处理错误的对象。

后续查找资源时，也需要区分“链接存在”“文件已下载”“内容与章节相符”和“版本完全对应”。目前下载的三份教师课件确实包含前三章主题，但来源页没有确认它们属于第五版。出版社能够打开第三章30页官方样章，也不能据此写成取得了完整前三章。来源的可信程度和覆盖范围，应随资料一起保存，而不是到了写报告时才凭印象补充。

这让我开始把出处看成知识的一部分。同一个公式来自指定教材、其他高校课件，还是本次生成的讲义，会影响我怎样使用它、用什么标准核对它。一个可靠的课程知识库，应该既能回答问题，也能说明依据来自哪里、是否适用于当前教学版本，以及哪里还不能确定。

## 三、概率论检索最容易丢失的，可能恰好是解题条件

概率论的问题不只是“有没有召回某个公式”。例如，使用条件概率需要分母事件具有正概率；把联合概率写成边缘概率的乘积，需要先确认独立；连续型变量换元时，还要保留支持范围与有效逆像。公式本身正确，脱离条件后仍然可能被错误使用。

以平方变换为例，若随机变量能同时取正值和负值，求分布时通常要考虑两个逆像。假如系统只检索到一个单调区间上的换元公式，却没有取到原变量的取值范围，最终推导可能写得很完整，结果却少算一部分概率。类似地，联合密度在三角区域内为常数，并不能仅凭“常数可以分解”就判断两个变量独立。

因此，我认为数学资料的整理单位不能只按段落长度决定，还要考虑一段推导是否完整。公式、适用条件、支持区域和反例，应尽量保持明确关联。以后实际分块和检索时，我想检查系统能否同时找到这些内容，而不只是看它是否提到正确的公式名称。这是根据题目结构提出的待验证风险，目前还没有实际运行检索来证明系统一定会犯这些错误。

## 四、文件之间的关系，比“文件都在”更重要

整理初期检查发现，题目索引引用的文档 ID 没有在资料清单中找到对应记录：题目、答案和清单虽然都能单独阅读，追溯关系却不完整。随后补齐关联，并在 v1.0.2 中通过文档 ID 存在性及相关结构检查。这个过程让我理解了统一编号的实际作用，也促使我把关联检查加入交付校验：从一道题应能回到正确来源，修改后也应能确认答案仍然对应原题。

题目数量也必须依赖完整索引。本包有45道原创主问题，显式小问和讲义例题另行统计；答案稿重复展示题目，不应再计一次。这些数量只说明本包收录了什么，不能拿来代替教材原书题量。以后新增真实课件或作业时，需要先逐题登记，再更新统计，而不是要求模型根据几个检索片段推测总数。

我倾向于把这类能够明确核对的工作交给程序，把解释概念、比较思路和组织提示交给模型。程序可以检查ID是否存在、哈希是否一致，却不能仅凭这些结果判断一道数学题是否解释充分。把两种能力分清楚，才能避免让一个“通过”的状态覆盖所有问题。

## 五、一次“通过”需要说明究竟检查了什么

本次对45道练习和6个讲义例题做了51项计算检查。它们能帮助发现枚举、归一化、积分或数值结果中的错误，但有限取值上的检查不能替代一般性证明，也不能证明整段文字推导没有漏洞。文件结构核验通过，同样不能代表题目已经与教师标准答案一致。

我认为这里至少要区分四件事：文件组织是否正确，数学结论是否成立，系统回答是否有充分依据，以及使用者是否能够独立解题。前一项通过，不能自动推出后一项通过。写周报时如果只说“验证通过”，读者很容易把一个局部检查理解成整个系统都已经可靠。

概率论尤其需要主动检查边界。例如，某一步是否除以了零概率事件，密度是否在有效区域外仍被使用，分段CDF在连接点是否满足要求。后续我希望在使用系统时保留一份“条件清单”，先检查这些前提，再看数值答案。这样既能检验模型，也能暴露自己是不是只记住了结论。

## 六、源码阅读要追到工具结果怎样进入下一轮

静态阅读时，我注意到聊天能力的入口比较短，具体流程还要继续追到父类中的通用循环。只看一个类名或入口函数，很容易停留在“这里调用了Agent”的表面理解。

我目前重点关注的是：上下文怎样决定可用工具，模型提出工具调用后如何分派，结果怎样以工具消息回填，以及循环在什么条件下继续或停止。对于课程学习，检索工具返回内容只是中间步骤，后面的回答是否保留了检索到的条件，还需要另外检查。系统有知识库工具，也不意味着每轮都必定使用它。

这也与本周学习的工具系统和 Coding Agent 形成了联系：工具返回成功，只能说明某个动作完成；最终目标是否达成，还需要外部判断。下一步我需要用一条真实提问记录，把静态代码中的输入、工具结果和最终回答对应起来，检查回答是否保留了检索证据中的适用条件。

## 七、我想用“撤掉帮助以后还能做什么”衡量学习效果

DeepTutor对我是否有帮助，最终需要落实到独立作答。我的下一步做法是先隐藏解析，自己写出随机变量、模型假设和解题路线；遇到困难时只请求一步提示，记录第一处错误。核对后再改变一个关键条件，例如把有放回抽样改为无放回，或把矩形支持区域改成三角区域，检查原来的方法是否仍然成立。

我准备分别记录“独立答对”“提示后答对”和“隔天变式独立答对”，避免把它们混成一个正确率。若系统能让我更快看到答案，但撤掉提示后仍然不能说明方法为什么成立，就还不能说学习效果得到了改善。这些比较尚未执行，后续需要留下真实作答记录。

下一阶段将按“指定版本资料核对—真实入库—检索轨迹核查—独立互测”推进，把 Agent 辅助完成的整理过程逐步转化为自己能够解释、复现和纠错的能力。课程资料包可以交给别人检查；我是否学会，也应该有同样具体、能够被追问的证据。
